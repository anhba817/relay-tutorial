<ChapterHeader id="3.3" />

Every error this platform sends carries four fields. Three of them are true.

```json
{
  "code": "not_found",
  "message": "no route for GET /v1/nope",
  "docs_url": "https://relay.example/docs/errors/not_found"
}
```

`relay.example` does not resolve, and constitution V calls `docs_url` a
reachable-page promise. That is a debt with a due date somewhere in Part 4, and it is
not what this chapter is about.

What this chapter is about is smaller and worse. Ask the platform which error codes it
can send, and then ask the registry which ones it documents, and the two answers do not
match.

## Four codes the registry never admitted

`ProtocolErrorFilter` turns a status into a code whenever the thrower does not name
one. It has done that since chapter 2.2, which widened the ladder because a 400 that
calls itself `internal_error` is a lie a client cannot act on. The ladder can produce
five codes. The registry declares one of them.

```text title="the ladder against the registry (excerpt)"
filter can emit : forbidden  internal_error  invalid_request  not_found  unauthorized
registry has    : invalid_frame  rate_limited  unauthorized  unknown_frame_type
                  wrong_credential_type

emitted and undeclared : forbidden  internal_error  invalid_request  not_found
```

Four codes have been going out on the wire for a chapter and a half while the object
that calls itself the failure vocabulary has never mentioned them. And because
`docs_url` is *derived* from the code, each one has been shipping a link to a page that
could not exist even after the docs site does — there is nothing to write the page
from.

The fix is to write them down.

<Why source="FR-024 · FR-027 · constitution V">
Registering the four is not bookkeeping. It is what makes the ladder **typable**: once
the registry is the source of the `ErrorCode` union, a ladder annotated `ErrorCode`
cannot emit a code that is not in it. The compiler starts doing the checking that
nothing was doing.
</Why>

## One place the URL is built

The same change adds `docsUrl`, and the reason is in the count. Before this chapter
three files build that string with a template literal:

```text title="who builds a docs_url (excerpt)"
services/gateway/src/session.ts:47
services/api/src/protocol-error.filter.ts:61
packages/service-kit/src/index.ts:85
```

Three is not a crisis. Three is the number *before* every chapter that adds a code also
adds a construction site, which is the shape this series has watched go wrong twice
already — a value declared in one place and rebuilt in several is a value that drifts
the first time somebody changes the wrong copy.

The code is the anchor and it goes in verbatim. No slug transform, no case change, no
separator swap: the reference page's headings **are** the codes. A transform would be a
second vocabulary to keep in step with the first, and the registry already is the
vocabulary.

The host stays a placeholder. What stops being a placeholder is the number of places
that have to change when it is not: one.

## A code you cannot mistype

The credentials chapter introduced the convention that a thrower may name its own code,
because `wrong_credential_type` is a distinction a status cannot carry. A 403 that calls
itself `forbidden` tells an integrator they lack a permission, when what they did was
present the wrong kind of credential.

What that convention could not introduce was any check on the string.

<Trap>
`HttpException`'s response is typed `unknown`. So `code: "wrong_credental_type"`
compiles, passes review, ships, and becomes a `docs_url` pointing at a page that does
not exist. Nothing in the toolchain reads that string. The first reader is a customer.
</Trap>

One function fixes it, because a function is a place where `ErrorCode` is the only thing
that fits:

```ts title="services/api/src/protocol-error.ts"

 * 403 that calls itself "forbidden" tells an integrator they lack a permission,

 *

 * response is `unknown`, so `code: "wrong_credental_type"` compiles, ships, and
 * becomes a `docs_url` pointing at a page that does not exist. Nothing in the
 * toolchain reads that string; the first reader is a customer.
 *

 * exactly what `ProtocolErrorFilter` already reads — `code`, `message` and the
 * optional `field` — so nothing about the envelope changes. What changes is that a
 * typo stops compiling. */
export function protocolError(
  code: ErrorCode,
  message: string,
  status: number,
  field?: string,
): HttpException {
  return new HttpException(
    { code, message, ...(field !== undefined ? { field } : {}) },
    status,
  );
}
```

The value it builds is exactly what the filter already reads, so nothing about the
envelope changes. What changes is that the typo above stops compiling:

```text title="the typo, now (excerpt)"
probe.ts(2,32): error TS2345: Argument of type '"wrong_credental_type"'
                is not assignable to parameter of type 'ErrorCode'.
```

And the filter gets the other half. The ladder is annotated, and the code a thrower
named is checked against the registry rather than trusted — `protocolError` makes an
unregistered string hard to produce, not impossible, because `HttpException` is still
public. The filter is the last place that can notice before the string becomes a URL.

`@relay/service-kit` declares **no dependencies at all** — that is the property that
lets every service use it without arguing about what else it drags in. Importing
`@relay/protocol` to build one string would trade that away for a convenience.

second copy of the ladder, which is normally the defect rather than the test — so it is

other direction: that somebody deleting an entry from the registry has to look at this
file.

## What this chapter leaves for later, on purpose

The host still does not resolve. `docs_url` will point at a real page when there is a
site to point at, and that is Part 4's — the debt this chapter closes is not the missing
site but the missing *ability to fix it in one place*.

The registry has five codes because the platform has five failures worth naming. Every
chapter after this one adds its own, and each addition is now three lines and a test
rather than a new construction site. That is the shape to notice: the contract is
cheapest to establish before there is anything to retrofit.

<Checkpoint tag="part3-ch3">
`pnpm typecheck`, `pnpm lint`, `pnpm build` and `pnpm test` all pass — 116 tests. The
`docs_url` string is built in exactly one place, and a mistyped code does not compile.
</Checkpoint>
